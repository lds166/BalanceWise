# 导入账单智能化：映射记忆 + 疑似重复检测 + AI 分类

## Context

导入账单的价值 = 从上传到入账省掉的手动修正次数。当前实现三个短板：
1. 分类映射是 24 条硬编码关键词规则（`CategoryMappingService.java:18-25`），且要求用户恰好建了同名分类，否则"未分类"；
2. 账户匹配按付款方式与账户名精确等值（`AccountMatcher.java:23-26`），"招商银行信用卡(1234)"这类带尾号的付款方式必然落到默认账户，账户流水失真；
3. 去重只认 external_id，手工记账与导入互相看不见，导账单会出现重复入账。

改造为三层分类流水线：**记忆（用户确认过的映射）→ 关键词规则 → AI 推荐 → 未分类**；账户匹配加"记忆+模糊"层；预览页增加"疑似重复"标记；用户修正通过"确认时统一勾选记住"沉淀为个人映射。AI 层走 OpenAI 兼容接口，用户将配置硅基流动，换供应商只改配置。

论文映射：第 4 章新增"分类匹配流水线"设计小节；第 5 章可做纯规则 vs 三层流水线的准确率对比实验。

分 **3 个提交**实施：① 记忆+模糊账户匹配 ② 疑似重复 ③ AI 分类层。

## 一、DB：新表 import_alias

两份 schema 同步更新（列定义保持一致）：`backend/src/main/resources/schema.sql`（H2 测试）+ `sql/init-mysql.sql`（MySQL 全量，含 COMMENT）。

```sql
CREATE TABLE import_alias (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  user_id BIGINT NOT NULL,
  alias_type VARCHAR(10)  NOT NULL COMMENT 'category=分类映射 / account=付款方式→账户',
  kind       VARCHAR(10)  NOT NULL DEFAULT 'any' COMMENT '分类映射存 expense/income；账户映射存 any',
  alias_text VARCHAR(128) NOT NULL COMMENT '分类=对方（空则商品名）；账户=付款方式原文',
  target_id  BIGINT       NOT NULL COMMENT 'category.id 或 account.id',
  target_name VARCHAR(64) NOT NULL COMMENT '名称快照（管理列表展示）',
  hit_count  INT NOT NULL DEFAULT 0,
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  UNIQUE KEY uk_alias_user_type_text (user_id, alias_type, alias_text, kind),
  KEY idx_alias_user (user_id)
);
```

kind 进唯一键使同一商户可同时有支出/收入两条记忆（退款行不会被支出记忆污染）；账户行统一 kind='any'。远程库 172.16.25.128 需手工执行此 DDL（增量，不动其他表）。

## 二、后端改动（backend/src/main/java/com/balancewise/）

### 1. 映射记忆 `importbill/service/ImportAliasService.java`（新建）
- 实体 `importbill/entity/ImportAlias.java` + `mapper/ImportAliasMapper.java`（BaseMapper、IdType.AUTO，遵循现有惯例）
- `learn(...)`：upsert——唯一键命中则 update target_id/hit_count+1，否则 insert；写前校验 target 归属（分类另校验 kind）
- `matchCategory(userId, type, platformCategory, item, counterparty)`：
  1. 记忆层：alias_text = counterparty 非空取之否则 item；查 alias_type='category' 且 kind=该行推导 kind；命中后加载 target 校验存在/归属/kind，通过返回（matchSource=memory）
  2. 规则层：现有 `CategoryMappingService.mapCategoryId` 不动（matchSource=rule）
  3. 都未命中 → null
- `list(userId)` / `delete(userId, id)`

### 2. `importbill/service/AccountMatcher.java`（改造）
匹配顺序：付款方式精确等值账户名 → 记忆表（alias_type='account'）→ 模糊匹配 → 默认账户兜底。
模糊匹配：normalize（去全/半角括号及其内容如"(1234)"、trim）后双向 contains；多处命中取名字最短（最具体）者；归档账户跳过。

### 3. `importbill/service/ImportService.java`（改造）
- **preview**：分类预填改调 `ImportAliasService.matchCategory`；`ImportPreviewRow` 增加回传字段 `platformCategory`、`payMethod`（供学习传递与前端展示）、`matchSource`、`duplicateSuspect`
- **confirm**：`ImportRowRequest` 增加可选字段 `payMethod`、`learnCategory`、`learnAccount`；入账循环完成后（同事务内）对 learn=true 且值有效的行 upsert alias（learnCategory 需 categoryId 与 key 文本非空；learnAccount 需 payMethod 与对应账户 id 非空）

### 4. 疑似重复（preview 内）
- 取全部行 occurredAt 的 min/max 扩 ±5 分钟，单次范围查询（走现有 `idx_txn_user_time`）拿 user 未删除流水的 (type, amount, occurred_at)
- 内存比对：同 type + 金额相等（setScale(2) compareTo==0）+ 时间差 ≤5min → `duplicateSuspect=true`
- 批内不做 suspect（同文件同分同时同额多为真实批量交易，注释说明）；confirm 不阻断 suspect 行，exact-dup 校验保持不变

### 5. AI 分类层 `importbill/ai/`（新建）
- `AiProperties`：首次引入 `@ConfigurationProperties(prefix="balancewise.ai")`，application.yml 新增：
```yaml
balancewise:
  ai:
    enabled: true
    base-url: https://api.siliconflow.cn/v1
    api-key: ${AI_API_KEY:}   # 未配置视为未启用，流程不受影响
    model: Qwen/Qwen2.5-7B-Instruct
    timeout-ms: 15000
    confidence-threshold: 0.6
    max-rows: 300
```
- `AiClassifier`：用 Spring 6.1 自带 `RestClient`（零新依赖）POST `{base-url}/chat/completions`，OpenAI 兼容报文 + `response_format: json_object`
  - 输入最小化：仅 lineNo/对方/商品名/平台分类/收支方向，**不含金额与时间**（隐私脱敏，论文素材）
  - 分类约束：把该用户 expense+income 分类（id+name）放进 prompt，只能从中选
  - 校验：categoryId ∈ 用户分类且 kind 匹配、confidence ≥ 阈值才采纳；行数超 max-rows 截断（超出走规则层并 notice）
  - 降级：任何异常 catch → log.warn + preview 附 notice="AI 分类暂不可用，本次已跳过"，绝不阻断导入
- preview 组装：memory/rule 未命中且非转账的行收集 → AI 分类 → 命中行 set categoryId + matchSource='ai'；`ImportPreviewVo` 增加 `notice` 字段

### 6. `importbill/controller/ImportAliasController.java`（新建）
- `GET /api/imports/aliases`（当前用户列表，updated_at desc）、`DELETE /api/imports/aliases/{id}`（归属校验后物理删除）；Result/@CurrentUser 惯例
