# 资产初始化指南（首次上手）

> 目标：系统里每个账户的余额 = 现实中的真实余额，资产负债表 = 你的真实身家。
> 核心原则一句话：**系统里的每一个账户 = 现实里每一个"钱待着的地方"或"你欠钱的地方"**。

## 第一步：盘点——去这几个地方抄数字

| 去哪抄 | 抄什么 |
|---|---|
| 微信「服务→钱包」 | 零钱余额、零钱通余额、**支付方式列表**（能看到绑了哪些卡） |
| 微信「花呗/分付」入口 | 当前欠款 |
| 支付宝「我的→余额/余额宝/花呗」 | 余额、余额宝、欠款 |
| 各银行 App | 每张储蓄卡余额、每张信用卡欠款 |
| 现金 | 钱包里的纸币硬币（记大概即可） |

**建账户清单的来源**：账单里出现过的所有「支付方式」+ 转账涉及的账户。
不确定时先上传账单**预览一次（不入账）**，预览"账户"列下拉里就是账单实际用到的支付方式原文，照着建齐。

## 第二步：建账户（结构模板）

| 现实账户 | 类型 | 子类型 | 名称怎么写 |
|---|---|---|---|
| 微信零钱 | 资产 | 微信零钱 | **照抄账单支付方式原文："零钱"** |
| 零钱通 | 资产 | 余额宝 | 照抄原文："零钱通" |
| 支付宝余额 | 资产 | 支付宝余额 | 照抄原文："余额" |
| 余额宝 / 余利宝 | 资产 | 余额宝 | 照抄原文："余额宝" / "余利宝" |
| 各银行储蓄卡 | 资产 | 储蓄卡 | 照抄原文，如"农业银行(4271)" |
| 现金 | 资产 | 现金 | 现金 |
| 花呗 | 负债 | 花呗 | 照抄原文："花呗" |
| 分付 | 负债 | 自定义 | "分付" |
| 各信用卡 | 负债 | 信用卡 | 带尾号，如"上海银行信用卡(0561)" |
| 借呗/白条/欠朋友的钱 | 负债 | 自定义 | 按实际 |

两条铁律：

1. **名称 = 账单"支付方式"原文**。导入时系统拿支付方式原文与账户名做精确→模糊匹配，
   "零钱""余额"这类 2 字名只有精确等值才命中（模糊比名要求 ≥3 字防止误伤），照抄原文最稳；
2. **一张真卡 = 一个账户**。同一张银行卡在微信和支付宝都用，就建一个账户，两个平台的账单都会命中它
   ——卡里的钱只有一个真相，不要按平台劈成两个账户。

不建议：房产/车等大件不建（系统是现金流台账，无流水支撑会让净资产虚高）；初期理财类可不建，后续用 transfer 补。

## 第三步：期初余额——两种定法选一个

账单只覆盖一段历史，而钱在账单开始之前就存在。期初余额的作用是把"历史存量"垫进来。

**路线 A：期初全填 0 + 导入后对账垫底（推荐，最省事）**

```
建账户（初始余额全填 0）
→ 导入账单（预览页出现绿色「已与官方汇总核对一致」再入账）
→ 账户页逐个「对账」：填今天的真实余额（负债按欠款正数填）
→ 差额 = 历史存量 + 小误差，自动生成校正流水垫平，余额立即 = 真实余额
```

**路线 B：期初填"账单起始日前一天"的真实余额**

适合查得到历史余额的情况（倒推：历史余额 = 今天余额 − 账单期间净变动）。
填对了导入完天然持平。⚠️ 基准日必须与账单区间衔接：期初填哪天的余额，就只能导那之后的账单。

## 第四步：导入与对账

1. 导入微信 xlsx（官方压缩包先解压）/ 支付宝 CSV；
2. 预览页确认绿色「**已与官方汇总核对一致**」——这是系统自动做的防丢行校验
   （微信按金额严格比对；支付宝官方统计含立减等优惠抵扣，金额差异会以口径说明形式提示，笔数永远严格核对）；
3. 逐行检查"账户"列：没匹配上的手动选一次并勾选「记住」，下次自动；
   **transfer（零钱充值/零钱通互转/信用卡还款）需要补选对方账户**——它们是自有账户间的移动；
4. 丢弃行说明：全部是"资金未移动/净额为 0"的行（交易关闭、失败、全额退款等），入账它们反而会
   虚增支出；预览页可「展开全部」逐条核对；
5. 入账后账户页逐个「对账」→ 差额为 0 完成；不为 0 会生成校正流水垫平（最后的安全网，可追溯）。

## 日常维护节奏

- 每月导一次当月账单 → 导入（重复区间 external_id 自动去重）→ 点对账确认差额 0；
- 现金消费手动记一笔；
- 对账差额突然不为 0 → 常见原因：现金消费没记、某支付方式没建账户、账单区间漏段；
- 银行流水接入后（后续版本），银行账单里「财付通/微信/支付宝」字样的行是平台代付，
  已被微信/支付宝账单记录，届时导入会自动过滤避免重复记账。

## 常见问题

**Q：账户名称和账单支付方式对不上会怎样？**
匹配失败不会丢钱：没选默认账户时该行留空标黄、强制手动补；选了默认账户则静默落到默认账户
（最隐蔽，入账前扫一眼账户列）；模糊误伤（名称互相包含）可能记错账户——所以名称照抄原文。

**Q：微信账单里"对方已退还""已退款¥0.37"这些行去哪了？**
部分退款拆成两笔入账（原支出 + 退款到账），净额与真实钱包一致；全额退款净额为 0 不入账；
失败/关闭订单资金未移动不入账。详见导入预览页的丢弃原因与核对提示。
